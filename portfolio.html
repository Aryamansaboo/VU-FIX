Core Problem & Insight

The Problem: Students submit maintenance complaints but face a "black box." They don't know who is handling it, when it will be fixed, or its current status.

Key UX Insight: By shifting from a static complaint form to a transparent tracking ecosystem with automated technician assignment, cognitive load on administrators is reduced and student anxiety is eliminated.

Usability Testing

Real feedback from 5 hostel students.

Testing Methodology

Objective: Identify friction points in the complaint submission and tracking flow.

Method: Moderated in-person testing with the live web prototype.

Tasks: 1) Log in to the system. 2) Review dashboard status. 3) File a plumbing complaint. 4) Review administrative assignment workflow.

Participant Findings

Participant Year Tested Component Observation / Actual Quote UX Interpretation
Aman Singh 4th Year Login Page "The login page should be more easy to use." Login hierarchy is complex; needs reduction of cognitive load and clearer CTA.
Megh 4th Year Dashboard "There is lots of clutteredness." Excessive secondary metrics competing with primary tracking information. Requires visual hierarchy cleanup.
Parth Pawar 3rd Year Assignment Workflow "The dashboard should assign the person directly. We should not do it manually. If it is a water issue, directly assign a plumber." Manual assignment creates bottlenecks. The system must use rule-based auto-assignment (Category → Specialist).
Anton Singh 4th Year UI Design "The UI is so refreshing, it's good." Positive validation of the visual aesthetic. Maintain modern dark/glassmorphic styling.
Anirudh Padhir 1st Year Full Application Overall feedback was good. Positive validation of the end-to-end user control and application flow.

Design Response

Based directly on this feedback, the following changes were implemented:

  • Simplified Login: Implemented a clean, tabbed interface to separate Student and Warden logins (Aman's feedback).
  • Focused Dashboard: Removed non-essential metrics, prioritizing active complaint status and a live feed (Megh's feedback).
  • Automated Assignment: Built logic in store.js to automatically map complaints (e.g., Plumbing → Suresh Sharma) immediately upon submission (Parth's feedback).

Behance Case Study

Hostel Maintenance System

Making maintenance transparent from complaint to resolution.

01 — The Problem

Hostel students frequently report maintenance issues (plumbing, electrical, Wi-Fi), but the process is a "black box." Students don't know if their complaint was read, who is assigned to fix it, or when it will be resolved.

02 — Why Transparency Matters

Without transparency, students suffer anxiety and repeatedly ping wardens. Wardens become bottlenecked manually assigning tickets to staff.

03 — UX Challenges & User Feedback

Through usability testing with 5 real students, we discovered:

  • Login was too complex (Aman Singh).
  • Dashboards were cluttered with useless data (Megh).
  • Manual technician assignment was a massive inefficiency (Parth Pawar).

04 — The Core UX Improvement: Automated Transparent Tracking

We redesigned the architecture to support Automated Assignment. Instead of:

Submitted → Waits for Warden → Assigned → Fixed

The new flow is immediate:

Water Issue Logged
Category: Plumbing
Auto-assigned: Suresh (Plumber)
Student Views Status & ETA

05 — Key Learnings

By automating the assignment logic based on categories, the dashboard instantly becomes a personalized tracking tool. The user feels heard immediately, and the UI shifts from a static form to a dynamic, transparent ecosystem.
